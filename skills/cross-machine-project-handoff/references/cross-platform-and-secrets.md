# 跨平台与敏感状态

迁移不是单纯的字节复制。Windows、macOS、Linux 的文件系统、权限、路径和工具链差异会改变项目行为。

## 跨平台检查表

### 路径

- 搜索版本化文本中的绝对用户目录、盘符、Homebrew 前缀、SDK 路径和临时目录。
- 把机器路径放入本地配置或环境变量，不把新机器路径硬编码成新的“通用值”。
- 检查脚本是否同时依赖 `\`、`/`、盘符、UNC 路径或 shell 专属语法。
- 检查 Git worktree、符号链接、IDE、MCP 和任务配置中的绝对指针。

### 文件系统语义

- 检查仅大小写不同的路径；大小写不敏感文件系统可能无法同时恢复它们。
- 检查 Unicode 文件名正规化，尤其是 macOS 与 Windows/Linux 之间。
- 检查 Windows 保留名称、尾随空格/点和过长路径。
- 检查符号链接是否仍是链接，而不是被复制成普通文本或目标内容。
- 检查 Unix 执行位和脚本 shebang；Windows 不以相同方式表达执行位。
- 依赖 `.gitattributes` 与项目约定处理换行；不要全局机械转换 CRLF/LF。

### 工具链

- 从项目权威文档、版本文件和锁文件确定版本，不照搬源机器的安装目录。
- 在目标重新安装 Flutter/Dart、Node、Python、Deno、Java、Xcode、Docker 等必要工具。
- 不复制 `node_modules`、虚拟环境、Flutter/Dart 构建产物、Pods、Gradle 缓存或其他平台绑定缓存，除非项目明确证明它们不可重建。
- 记录目标缺失的平台能力；例如 iOS 签名、Android SDK、硬件驱动或本机证书。

## 敏感状态分类

常见敏感状态包括：

- `.env` 与非样例环境文件；
- 私钥、证书、签名文件、服务账户；
- `.npmrc`、`.netrc`、云 CLI、包仓库和 Git 凭据；
- MCP、IDE、Agent 或本地工具配置中保存的令牌；
- 数据库连接串、生产/共享环境标识；
- 本地数据库本身包含的个人或业务数据。

示例文件（`.env.example`、`.env.sample`、模板证书说明）可以版本化，但必须确认它们不含真实值。

## 敏感状态规则

1. **先声明边界**：读取项目权威文档和 `.gitignore`，在内置规则之外，用 `--sensitive-path` / `--sensitive-glob` 声明项目专属秘密路径。`--sensitive-path` 同时保护该路径及全部后代，可用于文件或目录；显式规则优先于任何“可重建目录”剪枝。
2. **只盘点边界**：对已识别的敏感路径，普通清单仅记录相对路径、是否存在、是否 Git-ignored。
3. **不读值**：不要为了“确认一致”打开、打印、diff 或散列已识别的秘密内容。
4. **分类 unknown ignored**：审计器对未识别的 ignored 文件/目录只报告路径。逐项判断可重建、必须迁移或敏感；不要默认丢弃。
5. **单独通道**：使用用户批准的密码管理器、企业秘密管理器或加密离线载荷。
6. **最小权限**：只迁移目标任务需要的秘密；优先重新签发短期凭据。
7. **目标复核**：恢复后确认路径被 Git 忽略、文件权限合理，应用能以最小权限访问。
8. **泄漏处置**：若敏感文件已被 Git 追踪或出现在日志/清单中，停止普通迁移，报告风险并按用户授权轮换/清理；不要自行掩盖历史。
9. **对话即暴露面**：真实密码/令牌一旦出现在聊天、截图、终端历史、进程命令行或 Agent 上下文中，按已泄露处理。只把非秘密标签写入 `--compromised-credential-label`，完成轮换后重新审计。
10. **口令不进 argv**：不要用 `7z -p<password>`、环境回显或拼接 shell 命令传口令。优先使用交互式输入、密码管理器、系统凭据库或企业秘密通道；加密归档与口令分开传输。

文件名启发式永远不可能识别任意秘密。未声明且未被内置规则识别的普通 untracked 文件会按非敏感现场散列；因此在运行审计前补齐项目规则是安全前置条件。

清单中的远端 URL 只保留可安全解析的协议与主机，remote-helper、路径、用户信息、查询和片段会被遮蔽。清单仍会透露主机、目录结构和本机诊断，因此应保存在仓库外的受限位置；需要传输时加密，验证后按约定删除。

## 本地数据库与外部状态

- 先确认它是可重建测试数据、必要开发数据，还是生产/共享数据。
- 记录数据库引擎与版本、schema 版本、扩展、编码、时区和所需外部对象存储。
- 使用数据库原生一致性导出或项目规定的备份流程；不要在写入过程中复制裸数据库目录。
- 对导出文件记录摘要并加密；导入目标后运行完整性与迁移检查。
- 生产数据、支付、账户、内容权威库等高风险表面不属于普通项目搬迁；需要专门批准和流程。

## Codex 与协作上下文

项目内 Skill、AGENTS、规格和任务登记表通常应随 Git 迁移。机器级插件、全局 Skill、登录会话、连接器、浏览器状态和正在运行的 Agent 不会自动随仓库迁移。

审计器可以只读盘点 Codex 的机器级工具：

- 从全局 Skill 的 `SKILL.md` frontmatter 读取名称；
- 从插件 `.codex-plugin/plugin.json` 读取 id/version；
- 不读取 `config.toml`、会话、连接器凭据、浏览器数据或秘密值。

这份清单用于目标机重装/启用，不是复制整个 Codex Home 的授权。不要归档未知的机器级配置目录。

在交接胶囊中记录：

- 新环境需要安装/启用的 Skill 或插件名称，不复制未知机器级秘密；
- 仍在运行或必须停止的 Agent/自动化；
- 当前任务 claim、分支/worktree、验证证据与下一步；
- 新对话应先读取的权威文件及不可越过的安全边界。
